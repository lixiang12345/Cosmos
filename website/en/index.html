Why Cosmos

From chat window to operating system

Cosmos's first-class objects are tasks, runs, events, artifacts, and approvals — not messages. Once individual agent leverage is captured as organizational Experts and Automations, it compounds with every delivery.

Async by default

Submit a goal and walk away. Experts keep working in cloud sandboxes and pull you back through approvals and notifications when judgment is needed — no staring at a terminal.

Reusable Experts

Freeze team conventions, tool permissions, trigger conditions, and execution steps into reusable Experts instead of everyone re-tuning prompts. One engineer's polished workflow works for the whole org, out of the box.

Closed loop across tools

Start from Slack or GitHub; move through code changes, checks, PRs, and review feedback to a merge recommendation. Status and results flow back to the original thread — no lost context, no tool hopping.

Visible, controllable, auditable

Every plan, tool call, diff, approval, and external write has a status, a rationale, and an audit record. Low-risk steps advance on their own; high-risk steps must state their impact and wait for authorization.

Building Blocks

Seven first-class citizens, one delivery OS

Cosmos is neither a single agent nor a bare workflow engine. Experts, Environments, Sessions, Automations, Files, Workers, and Spaces are independent, configurable, shareable entities that compose into an orchestration system for the full SDLC.

Experts

A reusable workflow product surface: instructions, model, capabilities, environment, launch guidance, workers, and triggers packaged together — not a one-off prompt.

Environments

Flagship Workflow

Code review pipeline: a specialized team, humans at judgment points

When a PR opens, a Risk Analyzer routes it first: low risk auto-approves; high risk fans out to Deep Reviewer, Pair Reviewer, and Verifier in parallel, while a Memory Manager distills conclusions into organizational memory.

  • Nobody reads every PR line by line anymore. Humans appear only at architecture, product, security, and release judgment points.
  • Each Expert optimizes one intent. Reviewing and authoring pull in different directions; one giant prompt does neither well.
  • Conclusions carry evidence. Line comments arrive with test results and runtime proof, not vague opinions.

Safe by Default

Nothing fires until you say so

Agents get adopted at scale only when the security team can say yes. Cosmos builds the safety boundary into the product's foundation — quiet, not theatrical.

Triggers ship disarmed

New automations deploy off: dry-run once, confirm the behavior, then enable. Pausing never deletes configuration, and event filters run before a session is ever opened.

Approval gates on risk

External writes such as creating PRs or publishing comments must present impact, evidence, and rollback, then wait for approve / request-changes / reject — every decision recorded.

Secrets are write-only

Ciphertext can never be read back; queries return a last-four mask only. Provider credentials are injected server-side and never enter the browser bundle.

Isolation enforced in the database

Every tenant table runs PostgreSQL FORCE RLS; API and Worker use no-login runtime roles without table ownership, and refuse to start if the roles don't match.

OIDC + PKCE identity

Production Web uses Authorization Code + PKCE; access tokens live only in memory with a hard 300-second lifetime cap. 401, expiry, and logout clear identity immediately.

End-to-end audit

External events, user actions, agent writes, approvals, and results land in an append-only audit stream, searchable by type, source, status, and time.

Models & Context

A governed model catalog, structured context

No single-vendor lock-in, and no uncontrolled sprawl either: five models governed through one catalog, with credentials selected per model family. With Context Engine connected, Experts get equal-quality codebase context with fewer tokens — retrieval is authorized per Space and repository binding, and plugin keys stay server-side.

Run Anywhere

A local runtime in five minutes, a documented path to production

One command brings up the full Docker Compose runtime — PostgreSQL, API, Worker, and Web. Production ships with a standalone migration job, health probes, and runbooks for backup/recovery and observability.

terminal 
# Requires Node.js 22 · pnpm 11.7 · Docker
pnpm install
pnpm dev

# Web console
http://127.0.0.1:5173
# API health check
http://127.0.0.1:8787/api/health
  • Ordered startup. Compose waits for the database, starts the API, runs migrations, then brings up Worker and Web.
  • Fails safely instead of pretending. Without provider credentials the Worker stays unavailable and health-flagged; the control plane remains fully usable.
  • Production discipline built in. Startup migrations are forbidden in staging/production; backup-recovery, SLO alerting, and load drills each have a runbook.
