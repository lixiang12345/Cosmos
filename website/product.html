Product

一台面向软件交付的
Agent 编排操作系统

Cosmos 是软件研发团队的 AI 工程专家编排与治理平台：团队创建可复用的「专家」，让它们由人工、GitHub 或 Slack 事件触发，在隔离环境中完成代码任务，并在关键风险点请求人工审批。

Positioning

Cosmos 是什么

它的主要对象是任务、运行、事件、产物和审批，而不只是消息。它假设一个事实：个人工程师已经在用 Agent 写代码，但这些增益停留在个人终端里——组织既复用不了，也治理不了。

Cosmos 把这层能力抬到组织级：专家小队在可复现环境上，通过自动化值守完整研发生命周期，用文件共享记忆——默认安全、对话配置、人在判断点、工作发生在现场。

Cosmos 不是

只有代码补全能力的 IDE 插件
一次性问答聊天机器人
无审批、无审计的全自动生产发布工具
通用低代码工作流平台——首版只服务软件工程任务

适用团队：GitHub + Slack 使用成熟、有内部规范和重复任务的 20–500 人研发组织；以及被 PR 积压、Review 资源不足困扰的 EM / Tech Lead 与日常开发者。

Expert / 专家 — 可复用的工作流产品表面

一个专家打包了让工程工作流「像产品一样」运转所需的全部要素。配置页的形态像配置一个服务，而不是提示词游乐场：

字段组内容
身份与共享名称、描述、可见性（私有 / 共享）、稳定 ID；发布后的修订不可变，可追溯每一版
指令系统提示词、面向使用者的说明与输入引导（launch guidance）
模型从受控目录中选择默认模型，可按需替换
能力工具、MCP 服务器、Skills、集成——以可数的能力芯片呈现，而非模糊的「integrations」一句话
环境绑定的云端沙箱或自托管 Daemon 池
Workers可委托的其他专家列表，必须显式配置
触发器持久的事件绑定，新建默认关闭（disarmed）

Environment / 环境 — 算力与一致性

专家在环境里访问文件系统、仓库并执行代码与工具。环境与专家解耦：同一环境可挂多个专家，同一专家可换环境。

类型特点适用
云端沙箱每次会话从快照启动，可复现、相互隔离、可并发团队默认路径
自托管 Daemon运行在你的笔记本、VPC 或专用硬件上，磁盘可持久内网资源、受监管数据、专用硬件

环境打包镜像、仓库绑定、环境变量、Secret 引用、Hook 与网络策略；激活的环境修订不可变，供应过程有完整时间线。

Session / 会话 — 人机协作现场

会话是专家（行为）与环境（机器）的交汇处：人给任务、看回合、跟工具调用。对话永久保存；环境闲置时自动暂停，回来发消息即恢复。由触发器启动的会话可自动归档，归档后仍可打开。

  • 时间线：计划、步骤、工具调用摘要、日志、文件差异、测试与产物，可折叠，默认突出结论与异常。
  • 右栏是产品表面，不是装饰：Artifacts（PR、分支、链接等耐久产出）、Workers（委托树）、Files（工作区与组织记忆预览）、运行状态与环境信息。
  • 可见性与分享：共享专家或自动化开出的会话默认共享；个人专家默认私有；可按人授权并复制链接。

Automation / 自动化 — 事件到专家的值守指令

「自动化」在产品层等于「专家 + 它的触发器」。三种「事件进系统」的路径边界清晰：

概念谁创建生命周期匹配时行为
Trigger人，在专家配置里持久新开会话，事件负载作为首条消息
SubscriptionAgent 在运行中订阅随会话消亡事件投递进已有会话
Automation产品层视图= 专家 + 其触发器作为值守指令统一管理、启停

触发源覆盖 github、gitlab、linear、slack、pagerduty、schedule（五段 cron + 时区，单例执行：上一跑未完则跳过）与 webhook（JSONLogic 过滤，在开会话之前执行）。事件日志记录全部入站事实，运行历史记录专家的实际响应——两个问题分开回答。每条触发器可设每分钟运行上限。

Files / 文件 — 跨会话的组织记忆

文件活得比 VM 久。它不是用户上传箱——专家把工作副作用写进去，回合边界自动同步。每次写入都有不可变版本与归因，删除是墓碑而非抹除。

作用域谁可见典型路径
User仅自己的会话user/notes/…
Organization全组织organization/pr-reviews/…
Workspace仅当前会话的活 VM/workspace

Skills 是文件系统里的特殊目录：把团队方法论写成技能文件，绑定到专家后会自动汇入其系统提示词。

Workers / 委托 — 为什么不是一个超级 Agent

专注的意图才有专注的质量。深度审查与写码的优化目标不同，一个大提示词做不好两边。Cosmos 提供三种委托方式：

方式是什么重量何时用
Worker另一个专家的独立会话，可打开、可审计重子任务需要独立环境或产生副作用
Subagent同一会话内的轻量 helper轻同仓库内的调研与校验
Expert-to-Expert两个专家通过集成协作（如 PR 评论）松耦合希望人在集成里看到协作并能介入

原则：优先单专家；需要委托时用 1–2 个边界清晰的 Worker，且必须显式配置——不隐式乱发。

Space — 多团队边界

Space 按团队分组专家、环境、会话、Secrets、MCP、Webhooks 与仓库。切换 Space 就是整套上下文切换：聚焦的列表、隔离的凭据、团队自己的默认专家与环境。每个组织有一个不可删除的 Default Space，未分配的资源归入其中。

Interaction Philosophy

四条交互哲学

这些不是口号，而是落在每个界面上的具体设计决定。

Advisor-first

对话式配置

成功用户通过 Advisor 对话完成配置，而不是点遍表单：连依赖 → 建环境 → 部署或定制专家 → 从会话数据分析调优。Advisor 走计划 → 差异 → 确认 → 执行的受控链路，只做低风险控制面写入；OAuth 与 Secret 操作始终保留人工步骤。

Safe by default

默认安全

新自动化部署即关闭：先试跑、再启用。暂停不删配置；事件过滤在开会话之前执行，不关心的事件零成本。合规团队先定义可自动通过的路径与审计，再放开自动批准。

Human at judgment

人在判断点

深度审查专家非交互、读结论即可；结对审查专家交互、人做终裁；风险分析专家负责路由，高风险时把人拉入。人的时间只花在架构、产品、安全与发布的判断上。

Meet the work

工作在现场

从 Web、手机浏览器、Slack 或 GitHub 事件进入，进度、审批和结果回写到原线程。不强迫任何人回到 IDE 侧栏，也不制造又一个信息孤岛。

Information Architecture

导航即世界观

「做工」（首页 / 会话）与「装系统」（配置）分开，因为日常用户与平台管理员的心智不同；「自动化」与「会话」分开，因为值守指令与对话记录是两种东西；「事件日志」与「运行历史」分开，因为入站事实与专家的实际响应回答不同的问题。

文件独立成组——它不是附件，是跨会话的记忆层。触发器挂在专家上——自动化页是「带触发器的专家视图」，不是第三套实体编辑器。

Under the Hood

契约驱动的前后端分离架构

共享契约包同时约束 API、Worker 与 Web，三端使用同一份生成类型；控制面写入具备幂等键、乐观并发、append-only 审计与 outbox。

Frontend

React + Vite

18 个生产界面覆盖会话、审批、自动化与全部配置目录；中英文双语，桌面与 390px 小屏都是一等公民；加载、空、错误、权限状态完整。

Backend

Fastify + PostgreSQL

权威 Session 状态机、SSE 实时事件流、版本化 SQL 迁移；全部租户表 FORCE RLS，运行角色无登录、无表所有权，配置不符即拒绝启动。

Execution

Worker 运行时

独立 Worker 进程执行会话回合，周期性写心跳；API 只有在存在新鲜心跳时才宣告执行能力——离线时控制面可读，绝不把未运行表示成成功。

Contracts

共享契约 + OpenAPI

Zod DTO 与运行时校验前后端共用；OpenAPI 契约随代码演进并有路由覆盖测试守护，文档与实现不允许漂移。

Storage

对象存储与配额

S3 兼容存储承载文件与产物，SHA-256 完整性校验、保留策略与孤儿回收、组织级存储配额。

Operations

可观测与演练

低基数指标、SLO 告警规则、备份恢复与 PITR 预检、负载与依赖故障演练脚本——生产纪律以 Runbook 形式随仓库交付。

Template Library

62 个专家模板，覆盖 11 个领域

从「工单到已合并 PR」到「告警根因分析进 Slack」，模板保留工作流意图与验收规则；组织只需追加仓库范围与本地约定，不必从零写提示词。

首个演示闭环使用三个模板：Ticket or task to a merged PR、Automated deep review on every PR 与 Unit-test coverage gap analysis and draft PR。
