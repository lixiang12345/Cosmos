Getting Started

快速开始#

五分钟在本地拉起完整运行时：PostgreSQL、API、Worker 与 Web 控制台。

环境要求

  • Node.js 22 与 pnpm 11.7
  • Docker（含 Docker Compose）
  • 可选：OpenAI 兼容的模型 Provider 凭据（用于真实执行）

安装与启动

terminal
pnpm install
pnpm dev

pnpm dev 启动 Docker Compose 运行时。Compose 会等待 PostgreSQL 健康后启动 API，API 完成数据库迁移后才启动 Worker 与 Web；Web 通过同源 /api/* 反向代理访问 API。

入口地址
Web 控制台http://127.0.0.1:5173
API 健康检查http://127.0.0.1:8787/api/health

配置 Provider 凭据

首次使用从 .env.example 复制一份 .env.local 并填写 Provider 配置。敏感配置只注入 Worker，不会进入浏览器构建产物。

没有凭据也能跑控制台。Worker 会保持失败并被健康检查标记为不可用，此时无法启动执行，但全部控制面（专家、环境、自动化、目录配置）仍可访问。这是有意的安全失败，不是故障。

只看前端演示

terminal
# 带 seed 数据的前端原型，不代表真实运行时
pnpm dev:demo

演示模式仅允许 loopback 本地身份，生产构建始终拒绝进入演示模式。

端口被占用时

terminal
PORT=8790 VITE_API_PROXY_TARGET=http://127.0.0.1:8790 pnpm dev

Concepts

核心概念#

Cosmos 的界面命名保持一致：中文界面统一用「专家」「会话」，不混用机器人、助手等称呼。

术语定义
Expert / 专家可复用的 Agent 定义：职责、指令、模型、能力、环境与策略的打包，发布后修订不可变
Session / 会话一次目标驱动的持续执行实例，可由人或事件创建；对话永久保存
Run / 运行会话中的一次执行尝试；重试会产生新的运行
Trigger / 触发器启动专家的手动或外部事件条件，挂在专家上，新建默认关闭
Environment / 环境执行代码和工具的隔离运行空间：云端沙箱或自托管 Daemon
Approval / 审批对高风险写操作的人工决策记录，展示风险、影响、证据与过期时间
Artifact / 产物Diff、提交、PR、报告、测试结果等可交付结果，跨会话可检索
Space团队边界：专家、环境、会话、凭据按 Space 隔离，切换即切换整套上下文

更完整的概念阐述见产品介绍 · 七个一等公民。

Tour

界面导览#

左侧栏顶部是 Space 切换器；随后依次是做工区（新建会话、会话、产出物、审批）、自动化区、文件区与配置区。任何页面按 ⌘K 打开命令面板，输入即可跳转界面或执行动作。

区域包含界面回答的问题
做工Home、会话、产出物、审批「我现在要交付什么？」
自动化自动化列表、Run history、Events log「哪些值守指令在替我盯着？」
文件Organization、User 两棵记忆树「组织沉淀了什么经验？」
配置专家、环境、Daemons、集成、MCP、Skills、Webhooks、Secrets、仓库、Spaces、设置「这台系统如何被装配？」

界面提供中文 / 英文与浅色 / 深色主题，在 配置 → 设置 → 外观 中切换，偏好保存在本地。

Workflow

创建专家#

专家是团队工作流的产品表面。建议从内置模板起步（PR Author、Deep Reviewer、Pair Reviewer、Verifier、Ticket Dispatcher、Incident Investigator），再追加你的仓库范围与本地约定。

  1. 新建草稿

    进入 配置 → Experts，点击「创建专家」。可选空白开始，或选择模板预填指令与边界约定。

  2. 写清职责与指令

    名称与描述说明专家「做什么、不做什么」；System Prompt 承载工作流步骤与验收规则；User Instructions 与输入引导告诉使用者如何描述任务。

  3. 绑定环境与模型

    在 System 区选择运行环境与默认模型。模型来自受控目录（claude-fable-5、claude-opus-4-8、claude-sonnet-5、gpt-5.6-sol、grok-4.5），目录外模型会在任何网络请求前失败关闭。

  4. 配置能力与委托

    以芯片形式添加工具、MCP 服务器与 Skills；在 Workers 区显式列出可委托的其他专家。能力越少越好——最小权限是默认姿势。

  5. 设置可见性并发布

    私有专家只有自己可用；共享专家全 Space 可用。「保存草稿」随时可改；「发布」生成不可变修订——线上跑的永远是明确的某一版。危险区提供停用与归档，归档不删除历史。

发布 ≠ 自动运行。专家自带的触发器发布后仍是关闭状态，去自动化里显式启用才会响应事件。

Workflow

配置环境#

在 配置 → Environments 点击「创建环境」，先选类型再进表单：

类型说明选它当
Cloud 沙箱每次会话从快照启动；可复现、相互隔离、可并发团队默认路径
Daemon 池自托管进程注册为执行节点，带能力标签与并发槽位，按心跳判定在线需要内网资源、受监管数据或专用硬件

环境配置包含：基础镜像、仓库绑定（决定专家能检出哪些代码库，也是 Context Engine 检索的授权边界）、环境变量、Secret 引用（从当前 Space 的 active Secret 中下拉选择）、Hook 与网络策略。

环境修订同样「激活即不可变」。供应失败可以重试；停用不影响历史会话的记录。Daemon 节点在 配置 → Daemons 中管理，可随时启停单个节点。

Workflow

发起会话#

从 Home 启动

选择专家后，输入框的引导语会随专家的 launch guidance 变化。描述目标而不是步骤——步骤是专家的事。可在真实部署中先用 Context Engine 预检代码库证据，确认后作为「非可信仓库证据」附加到首条消息。

读懂时间线

会话时间线按回合展示计划、步骤、工具调用摘要、日志、文件差异与检查结果，默认折叠原始日志、突出结论与异常。SSE 实时推送更新，无需刷新。

右栏三件事

  • Artifacts：PR、分支、链接等耐久产出；也可手动补充链接。全局「产出物」页可跨会话检索。
  • Workers：本会话委托出的 Worker 树，每个都是可打开的真实会话。
  • Files：当前工作区与组织 / 个人记忆的预览。

生命周期控制

会话可暂停、恢复、取消；失败回合可重试（产生新运行）。列表支持置顶与归档，归档可恢复。对话永久保存；环境闲置自动暂停，回来发消息即恢复。分享面板可按人授予查看权并复制链接。

看不到「启动执行」按钮？说明当前部署没有在线 Worker（或执行开关未开）。控制面照常可用，可以先保存草稿；Worker 恢复心跳后即可启动。系统不会把未运行的会话表示成执行成功。

Workflow

自动化与触发器#

自动化页是「带触发器的专家视图」：每行一个专家，展开即见它的触发器与启停开关。

七类触发源

来源典型用法
github / gitlabPR 打开即启动审查专家；CI 失败即启动修复专家
slack频道内 @提及 即创建任务会话，结果回写原线程
linear / pagerduty工单流转、告警触发根因分析
schedule五段 cron + 时区；单例执行——上一跑未完成则跳过，不排队不回补
webhook万能入口；JSONLogic 过滤在开会话之前执行，不匹配的事件零成本

安全默认

  • 新触发器默认关闭。部署 → 试跑一次 → 确认行为 → 启用。
  • 暂停不删除。停用只是拨下开关，配置与历史完整保留；移除触发器也不影响专家本身。
  • 限流兜底。每条触发器可设每分钟最大运行数，异常风暴不会打爆环境。
  • 阅后即焚可选。触发器启动的会话可自动归档，归档仍可打开审计。

两本账

Events log 记录全部入站事件与脱敏后的负载——「外面发生了什么」；Run history 记录专家实际被触发的运行——「我们做了什么」。排查「为什么没触发」永远先看前者，再看后者。

Workflow

处理审批#

专家准备执行高风险动作（外部写操作、危险工具调用）时，运行会停在审批门。审批卡片展示动作内容、影响范围、依据证据与过期时间。

决策效果
批准动作执行，决策与决策人进入审计流
要求修改把意见退回给专家，专家调整后再次请求
拒绝动作不执行，会话按专家策略继续或收尾

处理入口有两个：审批页的统一收件箱（跨会话汇总，适合值班视角），或会话时间线内就地处理（上下文最全）。过期未处理的审批会失效，专家不会拿着过期授权执行动作。

Workflow

文件与 Skills#

文件页有两棵树：Organization（全组织共享）与 User（仅自己会话可见）。它们不是上传箱——专家在工作中把审查结论、规范摘要、排查笔记写进去，下一个会话、另一个专家、你的队友都能读到。

  • 每次写入生成不可变版本并记录归因（哪个专家、哪个会话）；删除是墓碑，不是抹除。
  • 会话内还有第三个作用域 /workspace：当前 VM 的活盘，只在会话内可见。
  • 存储走 S3 兼容对象存储，带 SHA-256 完整性校验与组织级配额。

Skills：把方法论文件化

在 配置 → Skills 维护技能条目（如「我们的迁移安全清单」）。专家绑定技能后，内容会按名称有序汇入其系统提示词——团队最佳实践从口口相传变成组织默认。

Configuration

集成与凭据#

Integrations 集成

支持 github、gitlab、slack、jira、pagerduty、linear、datadog 与 custom 八类。一次连接，任意专家可听其事件。卡片显示连接状态与健康度；action_required 时提供修复入口，断开与归档是两个不同操作。

MCP 服务器

三种传输：stdio（填启动命令）、sse / http（填端点地址）。提供 Atlassian、Sentry、Stripe、Figma 等伙伴预设一键预填。注册后以能力芯片出现在专家编辑器中。

Webhooks

创建后获得专属投递地址（POST …/webhooks/{id} + Bearer 鉴权）与只显示一次的签名密钥（whsec_…）——请立即保存，之后任何界面只能看到末四位。界面提供可复制的 curl 测试命令。仅接受 HTTPS 目标。

Secrets

名称须符合 ^[A-Z][A-Z0-9_]*$（如 DEPLOY_TOKEN）。密文写入后不可读回：数据库层面就不授予密文列的查询权限，任何查询只返回末四位掩码。环境通过引用使用 Secret，轮换时替换引用即可。

Repositories 仓库

登记 GitHub / GitLab 仓库与默认分支，是环境仓库绑定与 Context Engine 检索授权的基础。连接状态异常会显式标记为 action_required。

密钥纪律：Provider API Key 从 Secret Manager 注入 Worker 进程；浏览器构建产物、URL、localStorage、日志与截图中永远不应出现任何明文密钥。

Operations

部署与运维#

构建生产镜像

terminal
docker build -f apps/api/Dockerfile -t cosmos-api .
docker build -f apps/web/Dockerfile -t cosmos-web \
  --build-arg VITE_OIDC_AUTHORITY=https://identity.example.com/ \
  --build-arg VITE_OIDC_CLIENT_ID=cosmos-web \
  --build-arg VITE_OIDC_AUDIENCE=cosmos-api \
  --build-arg VITE_OIDC_REDIRECT_URI=https://cosmos.example.com/auth/callback \
  --build-arg VITE_OIDC_POST_LOGOUT_REDIRECT_URI=https://cosmos.example.com/ \
  --build-arg VITE_OIDC_SILENT_REDIRECT_URI=https://cosmos.example.com/auth/silent-callback .

两个运行镜像都使用非 root 用户并内置健康检查。Web 容器启动时把同源 /api/* 反代到 COSMOS_API_UPSTREAM，并用 COSMOS_CSP_CONNECT_SRC 等变量显式列出 IdP / API 所需的 HTTPS origin。

迁移是独立作业

staging / production 禁止 API 启动时迁移。发布流程先以同一镜像运行 node dist/migrate.js 迁移作业，成功后再滚动 API。迁移身份负责建表与运行角色加固；API / Worker 登录身份只获得对应角色 membership，无表所有权——角色不符即拒绝启动（fail closed）。

生产必需配置

组件关键变量
APINODE_ENV=production · AUTH_MODE=oidc · DATABASE_URL · CORS_ORIGIN · OIDC_ISSUER / OIDC_AUDIENCE / OIDC_JWKS_URI · SECURITY_AUDIT_HMAC_KEY（配套稳定的 …_KEY_ID）
Worker唯一且稳定的 WORKER_ID · AGENT_PROVIDER_GPT_API_KEY / AGENT_PROVIDER_CLAUDE_API_KEY / AGENT_PROVIDER_GROK_API_KEY（Secret Manager 注入）· EXECUTION_ENABLED=true
WebVITE_AUTH_MODE=oidc 及 OIDC public client 配置；缺失身份配置时显示错误，而非静默进入演示模式

探针与指标

  • GET /api/health —— 唯一公开的存活探针。
  • GET /api/ready —— 受鉴权保护，校验数据库与迁移状态；同时拒绝 pending 与未知迁移历史。
  • GET /api/metrics —— 仅在配置 METRICS_SCRAPE_TOKEN 时开放，输出低基数 HTTP / SSE 指标。

Worker 周期性写数据库心跳；API 只有在存在新鲜心跳时才向 Web 宣告执行能力。Worker 下线时控制面保持可读，会话草稿可保存。

质量门与 Runbook

terminal
pnpm check          # lint + typecheck + tests + build
pnpm openapi:lint   # API 契约校验

仓库随附三本运维 Runbook：PostgreSQL 备份与恢复（含 PITR 预检与季度演练）、Observability 与 SLO 告警、负载 / 依赖故障演练。CI 强制执行冻结锁文件安装、集成测试、备份恢复验证、镜像扫描与脱敏密钥扫描。

故障排查#

无法启动执行 / 发送消息按钮不可用

这是执行能力未就绪的诚实呈现，按顺序检查：Worker 容器是否健康（心跳是否新鲜）→ .env.local 是否配置了 Provider 凭据 → EXECUTION_ENABLED 是否为 true。控制面不受影响，配置工作可以照常进行。

触发器没有开出会话

先看 Events log：事件是否到达、是否被过滤条件挡下；再看 Run history：是否命中每分钟限流或触发器仍处于关闭状态。日程触发器是单例执行——上一跑未完成时会跳过本次，属预期行为。

默认端口被占用

用 PORT=8790 VITE_API_PROXY_TARGET=http://127.0.0.1:8790 pnpm dev 同时覆盖 API 监听端口与 Vite 代理目标。

跨域访问 API 被拒绝

分离部署且跨域时，需同时设置 VITE_API_BASE_URL 与逗号分隔的 VITE_API_ALLOWED_ORIGINS，否则浏览器会在发送 Bearer token 前拒绝请求——这是防止凭据误发的保护。

Context Engine 连接失败

staging / production 始终要求 HTTPS 端点。本地 Compose 访问宿主机插件可用 http://host.docker.internal:8790，并仅在本地 .env.local 设置 CONTEXT_ENGINE_ALLOW_INSECURE_HTTP=true。同时确认当前 Space 的激活环境已绑定目标仓库——绑定是检索的授权边界。

常见疑问

  • Secret 填错了想看一眼？看不了。密文写入后不可读回，重新创建一个正确的并更新引用。
  • 归档会丢数据吗？不会。会话、触发器、目录条目的归档都保留完整历史，多数可恢复。
  • 为什么模型列表不能自定义？目录由共享契约治理，目录外模型直接失败关闭——这换来的是凭据按模型族隔离与行为可预期。

还没解决？仓库 docs/ 目录包含产品需求、生产架构基线与三本运维 Runbook，覆盖比本手册更深的边界与恢复流程。
